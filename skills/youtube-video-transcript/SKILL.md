# YouTube Video Transcript

설교 내용은 기존 YouTube 자막만 사용해 처리한다. 정리본의 성경 인용 원문은 토브성경 개역한글 CLI로만 조회한다. 필요한 뉴스·역사 등 외부 사실 확인은 아래 별도 규칙을 따른다.

사용자가 `설교 요약해줘`, `설교 정리해줘`처럼 짧게 요청해도 아래 전체 설교 워크플로를 적용한다. 링크가 없고 현재 대화에서도 대상 영상을 특정할 수 없을 때만 링크를 요청한다. `요약`이라는 표현을 이유로 교정 전문·검수 단계를 생략하지 않는다.

## 설치·다른 사람에게 전달

설교 작업에는 자막 추출 도구뿐 아니라 토브 CLI와 동봉된 성경 데이터가 필요하다. 새 컴퓨터에 설치하거나 토브 명령/패키지가 없으면 [토브 설치·전달 안내](setup.md#토브-cli-설치와-스킬-전달)를 읽는다. 스킬을 공유할 때 `SKILL.md` 하나만 보내지 말고 템플릿·스크립트·설치 안내가 포함된 폴더 전체를 전달한다. 토브 CLI는 같은 공개 저장소에서 계정 없이 내려받아 설치한다. 관리자가 전달한 wheel 파일로도 설치할 수 있다. 설치 요청 없이 계정 권한·시스템 설정을 변경하거나 인증정보를 스킬에 넣지 않는다.

## 안전 경계

- 수동 자막을 우선하고 자동 자막을 차선으로 사용한다.
- 모든 `yt-dlp` 작업에 `--skip-download --no-playlist`를 사용한다.
- 영상·음원 다운로드, MP3, ffmpeg 변환, Whisper·STT를 금지한다.
- 자막이 없으면 우회하지 않고 중단한다.
- 프록시나 제3자 전사 API를 사용하지 않는다.

## 자막 추출

```bash
yt-dlp --skip-download --no-playlist --dump-single-json "VIDEO_URL"
yt-dlp --skip-download --no-playlist --list-subs "VIDEO_URL"
yt-dlp --skip-download --no-playlist --write-subs --sub-langs "LANG" --sub-format json3 "VIDEO_URL"
yt-dlp --skip-download --no-playlist --write-auto-subs --sub-langs "LANG" --sub-format json3 "VIDEO_URL"
```

한국어는 `ko-orig`, `ko` 순서로 선택한다. 결과 폴더에 자막·메타데이터 외 영상/음원 파일이 없는지 확인한다.

## 설교 필수 워크플로

`YouTube 링크 → 기존 자막 → 내부 교정 전문·성구 목록 → 토브 원문 일괄 조회 → 시간순 설교 정리 → 내부 검수·형식 검증 → 메모용 형식 변환·내용 동일성 검사 → 옵시디언용·메모용 MD 각각 1개 첨부`

PDF는 사용자가 요청할 때 같은 검수 완료 정리본으로 변환·시각 검수하여 추가 전달한다. 기본 작업에서는 PDF를 만들지 않는다.

전사만으로 완료하지 않는다.

### 1. 범위와 자막 확인

- 제목, 채널, 게시일, 길이, 설교자, 자막 종류를 확인한다.
- 설교 시작과 끝을 식별한다.
- 찬양·광고·진행자 발언은 제외하되 대략적인 범위를 기록한다.

### 2. 내부 교정 전문

설교자의 실제 순서, 주장, 질문, 반복, 예화와 강조를 보존한 전체 전문을 만든다.

- 롤링 자막 중복과 잡음만 제거하고 문장·문단·명백한 인식 오류를 교정한다.
- 성경 권명, 인명, 지명과 장절의 명백한 오류를 바로잡는다.
- 요약, 미화, 교리 보충, 논리 재구성으로 뜻을 바꾸지 않는다.
- 의미 있는 반복과 질문을 남기고 불확실한 말은 `[불명확]`으로 표시한다.
- 내부 타임스탬프를 보존하되 전문은 사용자가 요청할 때만 전달한다.
- 5분 단위 자막을 이어 붙이거나 단어만 일괄 치환한 파일은 교정 전문으로 인정하지 않는다. 처음부터 끝까지 자막과 대조하여 문장·문단을 다듬고, 각 구간의 주장·성구·예화가 전문에 남았는지 확인한 뒤 다음 단계로 넘어간다.

### 2-1. 성구 확인: 토브성경 개역한글만 사용

성구의 본문 기준은 토브성경 개역한글 하나다. 설치된 `tov` CLI와 함께 사용하며, `tov-bible` 스킬이 있으면 그 조회 지침을 따른다. 다른 개역한글 사이트·번역본·모델 기억으로 대체하거나 토브의 옳고 그름을 교차 검증하지 않는다.

- 교정 전문에서 장절과 직접 낭독·인용/단순 언급/의역을 구분해 성구 목록을 만든다. 장절이 불명확하면 토브 검색과 설교 문맥으로 특정하고, 특정할 수 없는 인용을 지어내지 않는다.
- 중복 장절을 모아 JSON 문자열 배열로 준비하고 `tov batch "<성구 목록.json>" --json`으로 한 번에 조회한다. 추가로 발견한 장절만 추가 조회한다. 반환된 항목별 성공·오류를 확인하고 결과를 내부 작업 폴더에 보관한다. 필요하면 `tov verse "벧전1:13" --json`, `tov passage "벧전1:13-17" --json`, `tov search "은혜를 온전히" --phrase --json`을 사용한다.
- 정리본의 성구 콜아웃에는 반환된 `text`를 그대로 넣는다. 철자·띄어쓰기·본문 문장부호를 교정하거나 자막 표현으로 덮어쓰지 않는다. 여러 절은 순서대로 제시하고, 발췌는 원문의 연속 부분을 그대로 사용하며 생략 지점에는 줄임표를 둔다. 상자의 따옴표·줄바꿈은 표시용이다.
- 내부 교정 전문은 설교자의 실제 발언을 보존한다. 설교자가 의역·설명한 말을 토브 전문으로 일괄 바꾸거나 실제로 전문을 낭독했다고 꾸미지 않는다. 토브 표기와 다른 실제 발언이 있으면 내부 성구 대조표에 구별해 기록하되, 정리본 성구 상자는 토브를 기준으로 한다. 단순 언급·의역에 새 직접 인용 상자를 만들지 않는다.
- 토브 결과를 그대로 사용해 새 인용을 작성했다면 `tov verify`를 추가로 반복하지 않는다. 기존 문서나 이미 작성된 인용을 대조해야 할 때만 `tov verify "<정리본.md>" --json`으로 토브와 한 번 비교한다. 이는 다른 성경과의 더블체크가 아니다.
- 출처 URL·데이터 버전·SHA-256은 내부 검수 기록에 한 번 남긴다. 이는 로컬 스냅샷의 식별 정보이며 매번 웹 접속·로그인·REA 분석·본문 재다운로드를 하지 않는다. `tov data check`도 첫 설치나 데이터 오류 때만 별도로 실행한다.
- `tov`가 없으면 같은 환경의 `python3 -m tov_bible` 또는 Windows의 `py -m tov_bible`을 사용한다. 패키지 부재·장절 오류·데이터 오류는 확인 한계로 보고하고 해결 전에는 성구 확인 완료라고 하지 않는다. 다른 출처로 우회하지 않는다.

### 3. 사용자용 정리본: 단일 시간순 구조

사용자가 설교를 들으며 문서를 위에서 아래로 그대로 따라갈 수 있어야 한다. 설교의 실제 시간·논리 순서 하나를 문서의 중심축으로 삼는다.

**고정 형식:** 매번 [정리본 템플릿](templates/sermon-study.md)의 구조 그대로 기준 정리본인 옵시디언용 MD를 작성한다. 메모용은 이 파일에서 3-2의 표시 형식만 변환한다. 이전 정리본을 매번 열어 볼 필요는 없다. 템플릿을 새로 만들거나 바꿀 때, 또는 검증을 통과했는데도 형식·서술 밀도가 모호할 때만 2026-09-20 「울지 말라」 승인본을 참고한다. 그 설교의 내용은 가져오지 않는다. 이는 **비교 대상만 고정한다는 뜻이지 검수 강도를 낮춘다는 뜻이 아니다.** 새 설교마다 대단락 수는 달라도 제목·메타데이터·시간 표기·성구 제시 방식·결론의 위치는 바꾸지 않는다.

문서 순서:

1. 제목
2. `## 설교 정보` — 설교자, 일자, 채널, 영상, 핵심 본문, 정리 기준
3. 한 문장 주제
4. 번호가 붙은 시간순 설교 본문
5. 설교의 결론
6. 한 문장 결론

시간순 본문 작성 규칙:

- 설교자의 실제 논리 전환을 기준으로 번호를 나눈다.
- 기준 정리본의 타임스탬프는 각 번호 대단락 제목에만 `(약 00:00~00:00)` 형식으로 한 번 쓴다. 메모용에서는 같은 시간을 해당 제목 바로 아래에 한 번 표시한다. 1시간을 넘는 영상은 분을 누적해 `61:00`처럼 표시한다.
- 각 번호 안에 그 시점의 주장, 성구 본문, 성구를 인용한 이유와 앞뒤 논지의 연결, 예화의 내용과 가르침, 적용을 모두 함께 적는다. 이 연결은 설교 밖에서 분석하는 문장이 아니라 설교 내용 자체로 풀어 쓴다.
- 직접 낭독·직접 인용·언급·의역을 필요할 때 자연스럽게 밝힌다.
- 설교자가 직접 낭독·인용한 성구는 해당 위치에 `> [!info] **성구**` 다음 줄 `> “토브에서 조회한 원문 또는 줄임표를 둔 정확한 발췌”` 형식으로 제시하고, 바로 뒤에 그 구절의 뜻과 인용한 이유가 드러나도록 설교 내용을 이어 쓴다. 장절만 적고 본문을 생략하지 않는다. 단순 언급한 성구는 인용문을 만들지 말고 해당 말씀과 이어지는 가르침을 본문에 적는다.
- 성구는 단순 나열하지 말고 등장 즉시 그 말씀으로 전한 가르침을 직접 풀어 쓴다. `이 구절을 근거로 논지를 뒷받침한다`처럼 인용 행위를 해설하는 문장으로 대신하지 않는다.
- 예화도 등장 즉시 실제 내용과 그 예화로 전한 가르침을 함께 적는다. `이 모습을 예로 들어 뜻을 구체화한다`처럼 예화의 기능을 평가하지 말고, 예화에서 이어지는 설교의 설명과 권면을 직접 쓴다.
- 뒤에서 별도의 `핵심 본문`, `주요 성구`, `핵심 인용문`, `예화`, `교리적 주장`, `적용 질문` 목록으로 같은 내용을 다시 분류하거나 반복하지 않는다.
- 독자가 앞뒤로 스크롤하지 않아도 최초 등장 위치에서 이해가 끝나게 한다.
- 쉬운 문장으로 정돈하되 설교자가 하지 않은 연결이나 결론은 만들지 않는다.
- 정리본의 목적은 목사님이 하신 설교의 뜻과 흐름을 충실히 옮기는 것이다. 작성자가 말씀의 옳고 그름을 판정하거나 평론·반론·칭찬을 덧붙이지 않는다. `목사님은 … 강조하셨다`, `설교자는 … 주장한다`, `설교자의 설명에 따르면`처럼 일반적인 설교 내용을 제삼자의 주장으로 소개하지 않고, 그 설명과 권면 자체를 쓴다. 외부에서 확인해 덧붙인 자료는 기존 외부 보충 형식으로만 구분한다.
- 사용자용 정리본은 목사님이 말씀을 전하시는 듯한 쉬운 존댓말로 쓴다. 한 문장 주제·본문·결론과 문장형 소제목에는 `~입니다`, `~합니다`, `~해야 합니다`처럼 자연스러운 종결을 사용한다. 명사형 제목·정보 항목은 간결하게 유지한다. `뜻을 구체화한다`, `논지에 연결한다`, `예화의 역할을 보여 준다`처럼 밖에서 관찰·분석하는 문장도 피한다. 주장·질문·설명·권면 자체를 바로 적고, 원문에서 함께 권면한 내용은 `우리도 … 해야 합니다`처럼 그 관점을 살린다. 원문에 없는 호칭·질문·권면을 말투를 살린다는 이유로 추가하지 않는다. 원문에 있는 다른 사람의 말이나 불확실한 표현은 그대로 구별해 보존한다. 설교의 뜻을 보존한 정리이므로 문단 전체를 직접 인용처럼 꾸미거나 실제로 하지 않은 발화를 지어내지 않는다.
- 문체 예: `가장의 모습을 예로 들어 ‘정신을 차린다’는 뜻을 구체화한다` 대신 `정신을 차린다는 것은 자기 신분과 책임을 잊지 않는 것입니다. 가족을 책임져야 할 가장이 술과 노름에 빠져서는 안 됩니다. 구원받은 우리도 마음을 다른 데 빼앗기지 말고 깨어 기도해야 합니다`처럼 쓴다. 이는 말투의 예시이며, 내용은 해당 설교의 실제 발언에서 확인될 때만 쓴다.
- 성경 인용문과 다른 사람의 직접 인용은 확인된 원문 그대로 두고 존댓말로 바꾸지 않는다. 내부 교정 전문도 실제 발언을 보존한다. 외부 보충·성구 확인 안내는 존댓말로 쓰되 별도 자료임을 유지한다. 옵시디언용·메모용과 요청받은 PDF에 같은 존댓말 본문을 사용한다.
- 말투와 문장만 자연스럽게 다듬을 수 있다. 설교자가 하지 않은 주장·질문·적용·교리적 연결·강조를 새로 만들거나, 실제 발언보다 강하게 단정하지 않는다. 굵게 표시하는 등 시각적 강조를 추가할 때도 원자막과 교정 전문에서 같은 취지와 강조가 확인되는 기존 내용에만 적용한다. 근거가 없는 문장은 강조를 풀지 말고 문장 자체를 삭제하거나 원문에 맞게 고친다.
- 정리본은 전문보다 짧아도 되지만, 핵심 논지뿐 아니라 그 논지에 이른 질문, 반론, 중요한 반복·예화의 기능이 보이도록 한다. 각 시간 구간에서 무엇을 압축하거나 생략했는지 원자막과 대조하고, 논리 전환에 필요한 부분이 빠졌다면 보완한다.

### 3-1. Obsidian에서 읽기 좋은 최소 표시

기존 시간순 구성과 서술 밀도를 유지하고, Obsidian 기본 기능만 사용한다. 플러그인·CSS 설치를 요구하지 않는다.

- **성구:** 위의 `[!info]` 콜아웃을 사용한다. 짧게 인용한 구절도 빠뜨리지 않고 장절·본문·인용 이유를 같은 위치에 둔다. 접기 기호 `+`·`-`를 붙이지 않아 항상 펼쳐 보이게 한다. 기본 테마에서는 배경과 제목이 구분되며 실제 색상은 사용자의 테마를 따른다.
- **형광펜:** 원자막과 교정 전문에서 강조가 확인되는 기존 핵심 문장에만 `==문장==`을 적용한다. 번호 대단락마다 최대 한 문장이며, 강조할 근거가 없으면 생략한다. 성구 본문·장절·시간에는 형광펜을 넣지 않는다. 색상 이모지나 HTML로 문서를 꾸미지 않는다.
- **실선:** `---`를 설교 정보 뒤와 `## 설교의 결론` 앞에만 넣는다. 모든 단락이나 성구 사이에 반복하지 않는다.
- **외부 보충:** 아래 세 줄을 `[!example] 외부 보충` 콜아웃 안에 넣는다. 성구 상자와 구분하되, 외부 확인을 하지 않았다면 상자 자체를 만들지 않는다.
- **호환:** PDF를 요청받아 변환할 때 `[!info]`, `[!example]`, `==`가 그대로 인쇄되지 않도록 실제 인용 상자·강조 배경·구분선으로 렌더링한다. 변환기가 지원하지 않으면 임시 변환본에서 기호만 정상적인 인용/강조로 바꾸고, 사용자용 Markdown 내용은 보존한다. 이전의 일반 인용문 형식도 검증기가 계속 인식하도록 한다.

### 3-2. Apple 메모용 표시와 내용 동일성

검수한 옵시디언용 MD 하나를 내용의 기준으로 삼는다. 메모용을 따로 요약하거나 문장을 다시 쓰지 않는다. 내용을 수정해야 한다면 기준 정리본을 먼저 수정·검수한 뒤 메모용을 다시 변환한다.

- **성구:** `[!info]`를 제거하고 `> **성구**`, 빈 인용 줄 `>`, `> “본문”`으로 표시한다. 장절·인용문·뒤따르는 설명을 그대로 보존한다.
- **핵심 문장:** 기존 `==문장==`만 `**문장**`으로 바꾼다. 새 강조나 새 문장은 추가하지 않는다.
- **제목과 시간:** 번호·소제목은 그대로 두고 같은 `(약 00:00~00:00)`를 제목 바로 아래 별도 줄에 기울임꼴로 표시한다.
- **외부 보충:** `[!example] 외부 보충`을 `> **외부 보충**`으로 바꾸고, 확인·연결·출처 세 항목과 링크를 그대로 보존한다. 문단 순서와 두 구분선도 유지한다.
- **변환·검사:** [메모용 변환 도구](scripts/export_apple_notes.py)를 `python3 scripts/export_apple_notes.py --study "<검수한 옵시디언용 MD>" --output "<메모용 MD>"`로 실행한다. 이 도구는 표시만 변환하고, 표시 기호와 공백을 제외한 전체 내용이 같은 순서로 일치하는지 검사한다. 검사 실패 시 전달하지 않는다. 기존 메모용 파일만 검사할 때는 같은 명령에 `--check`를 붙인다.
- **가져오기 안내:** iOS·iPadOS 26 이상에서는 파일 앱에서 MD를 길게 눌러 `공유 → 메모`로 가져오면 리치 텍스트로 변환된다. [Apple 공식 안내](https://support.apple.com/ko-kr/102223)를 참고한다. Markdown 파일을 메모에 붙여넣기만 해도 서식이 변환된다고 안내하지 않는다.

기본 파일명은 `YYYY-MM-DD_설교자_공식 설교 제목_설교정리.md`(옵시디언용)와 `YYYY-MM-DD_설교자_공식 설교 제목_메모용.md`다. PDF를 요청받으면 `YYYY-MM-DD_설교자_공식 설교 제목_설교정리.pdf`로 만든다. 검수한 두 MD를 보존하고, 각 최종 파일명과 첨부파일 이름을 정확히 일치시킨다. 영상 ID와 작업용 표현은 내부 파일명에만 쓴다.

### 4. 외부 사실 확인

기본 출처는 설교 전문이다. 설교에 등장하는 뉴스·역사 사건·인물·연도·사회적 사실 등의 배경이나 사실 여부를 확인해야 설교의 예화를 정확히 이해할 수 있을 때 외부 확인을 한다. 확인할 필요가 없는 예화에는 외부 블록을 만들지 않는다.

- 뉴스·역사 등 외부 사실은 공신력 있는 출처로 교차 확인한다. 성경 인용 원문은 이 단계에 포함하지 않고 2-1의 토브 단일 기준을 따른다.
- 외부 보충임을 분명히 밝히고 출처 링크를 남긴다.
- 실제 사실, 설교자가 그 사건을 든 이유, 논지에서의 시사점을 짧게 설명한다.
- 인용 목적이 불명확하면 추정이라고 표시한다.
- 확인되지 않는 세부사항은 사실처럼 쓰지 않는다.

### 4-1. 외부 보충 표시 형식

설교 내용은 별도 표식 없이 자연스럽게 쓴다. 외부 검색으로 확인해 추가한 내용만 등장 지점에 아래 형식으로 표시한다.

> [!example] 외부 보충
> **보충 확인(외부 자료):** 확인된 사실과 설교 이해에 필요한 짧은 설명  
> **설교와의 연결:** 설교자가 이 사실을 인용한 이유 또는 논지상 시사점. 불명확하면 추정이라고 밝힌다.  
> **출처:** 기관명 또는 문헌명과 링크

- 외부 보충은 해당 번호 대단락 안에서 필요한 지점에만 넣어 시간순 흐름을 유지한다.
- 문서 끝에 따로 몰아 독자가 앞뒤로 오가게 하지 않는다.
- 외부 검색을 하지 않은 부분에는 표식을 붙이지 않는다.
- 성경 본문 확인은 `성구 확인`으로, 역사·과학·사회적 사실 조사는 `보충 확인(외부 자료)`으로 구별한다.

### 5. 원문 충실성

- 설교자의 말, 순서, 강조보다 작성자의 해석이 앞서지 않게 한다.
- 설교에 없던 배경, 교리, 예화와 평가를 임의로 추가하지 않는다.
- 직접 인용, 설교 내용의 의역, 외부 보충을 구별한다.
- 바꿔 쓴 문장은 의미가 같은지 전문과 다시 대조한다.
- 정리본의 모든 주장과 적용은 설교자의 실제 발언으로 역추적할 수 있어야 한다. 외부 확인 내용은 명시된 보충 블록에만 두고 설교자가 말한 것처럼 본문에 섞지 않는다.

### 6. 품질 검수

속도보다 정확성을 우선해 전체 전문과 정리본을 대조한다.

**매번 남길 검수 근거:** [내부 품질 검수 기록](templates/internal-qa.md)을 이번 영상의 작업 폴더에 복사해 실제 확인한 내용으로 채운다. 자막 전체를 빠짐없는 시간 구간으로 나누어 각 구간의 주장·전환·성구·예화를 교정 전문 및 정리본 위치에 대응시킨다. 직접 낭독·인용과 단순 언급을 나눈 성구 전수표, 확인이 필요한 외부 사실의 처리·출처도 남긴다. 기도·찬양 등 정리에서 제외한 구간은 제외 이유를 적는다. 표를 자동으로 채우거나 검수하지 않은 항목에 체크하지 않는다. 이는 내부 기록이며 사용자에게는 요청받지 않으면 보내지 않는다.

**전달 전 필수 게이트:** 매번 [정리본 템플릿](templates/sermon-study.md)에 맞게 작성하고 [형식 검증기](scripts/validate_sermon_study.py)를 `python3 scripts/validate_sermon_study.py --study "<검수한 옵시디언용 MD>" --transcript "<내부 교정 전문>" --audit "<내부 품질 검수 기록>" --captions "<원본 json3 자막>" --attachment-name "<옵시디언용 MD 파일명>"` 형태로 실행한다. 아래 의미 검수와 3-2의 메모용 변환·내용 동일성 검사도 모두 통과하기 전에는 전달하지 않는다. 이 구조 검증기는 기준 정리본에만 적용하고, 메모용의 표시 차이는 변환 도구로 검사한다. `--attachment-name`에는 기준 정리본의 실제 파일명을 준다. PDF를 요청받았다면 파일명·첨부 표시명 일치를 변환 후 별도로 확인한다. 스크립트 경로는 이 스킬 폴더를 기준으로 해석한다. 검증기는 구조·검수 기록의 완결성과 교정 전문의 지나친 축약 여부만 확인하므로 **기록의 진실성이나 설교 내용의 정확성을 보증하지 않는다.** 분량 검사에 걸리면 말을 억지로 늘리지 말고 자막과 전문을 구간별로 재대조한다. 이전 정리본과의 수동 비교는 템플릿 변경·형식 예외·모호한 검증 결과가 있을 때만 한다.

- 내부 교정 전문이 전 구간을 문장·문단 수준으로 교정한 결과인지 확인한다. 자막의 단순 이어 붙이기나 일괄 치환이면 이 단계로 되돌아간다.
- 주요 논지와 전환이 실제 순서대로 빠짐없이 들어갔는지 확인한다.
- 한 문장 주제·본문·결론과 문장형 소제목이 쉬운 설교식 존댓말인지 확인한다. 설교를 밖에서 분석·평가하는 3인칭 보고문은 뜻을 바꾸지 않고 설교의 설명·권면 자체로 고친다. 성경과 다른 사람의 직접 인용은 원문을 보존했는지 확인한다.
- 직접 낭독·인용한 각 성구의 본문 발췌와 인용 이유가 등장한 바로 그 대단락에 있는지 자막·교정 전문과 대조한다. 성구 개수는 설교마다 달라야 하므로 이전 정리본의 개수에 맞추지 않는다.
- 성구 상자를 2-1에서 조회한 토브 본문으로 작성했는지 확인한다. 형식 검증기의 PASS는 성구 원문 조회를 대신하지 않는다. 이미 사용한 토브 결과를 재조회하거나 다른 성경으로 이중 검증하지 않는다.
- 뉴스 등 외부 사실을 실제로 조사했다면 같은 대단락에 보충 확인·설교와의 연결·출처 세 줄이 모두 있는지 확인한다.
- 별도 유형별 목록이나 중복 때문에 순차성이 깨지지 않는지 확인한다.
- 기준 정리본의 타임스탬프가 번호 제목에만 있고, 메모용의 같은 시간은 제목 바로 아래에 한 번만 있는지 확인한다.
- 장절 오류, 과도한 해석, 설교에 없던 내용이 없는지 확인한다.
- 굵게 표시하거나 형광펜으로 강조하거나 핵심으로 내세운 문장이 있다면 해당 자막·교정 전문의 위치와 강조의 강도를 확인한다. 원문에서 확인되지 않으면 전달 전에 삭제하거나 표현을 낮춘다.
- 외부 사실은 필요한 경우에만 출처와 함께 분리되어 있는지 확인한다.
- 영상·음원 파일이 생성되지 않았는지 확인한다.
- 성구 콜아웃의 본문·인용 이유가 유지되고, 형광펜은 근거가 있는 문장에만 절제해 적용되었는지 확인한다.
- 두 MD의 문장·성구·시간·출처와 순서가 표시 형식을 제외하고 동일한지 확인한다. 이는 변환 중 내용이 바뀌지 않았다는 검사이며, 원문 충실성 검수를 대신하지 않는다.
- 최종 파일명과 첨부파일 표시명이 완전히 같은지 확인한다.

### 7. 전달

기본 전달물은 **같은 설교 정리본의 옵시디언용 MD 1개와 Apple 메모용 MD 1개**다. 두 파일을 모두 저장하고 같은 응답에서 용도를 구분해 함께 전달한다. PDF는 사용자가 요청할 때만 만든다. 이번 요청에서 특정 형식만 명시하면 그 요청을 따른다.

- **PDF 요청 시:** 검수와 형식 검증을 통과한 기준 정리본을 생략하거나 바꾸지 않고 변환한다. 문서의 순서와 제목·시간·성구·외부 출처를 유지한다. 한글 글꼴, 읽기 좋은 본문과 인용문 구분, 여백, 페이지 번호를 적용한다. 페이지를 이미지로 렌더링해 글자 깨짐·잘림·겹침·제목만 페이지 끝에 남는 문제를 확인한다. PDF 추출 텍스트도 기준 정리본과 대조해 내용 누락이 없는지 확인한다.
- **저장 위치 안내만으로 전달을 끝내지 않는다.** 이 대화 환경이 지원하는 다운로드 가능한 파일 첨부 또는 출력 파일 인용으로 두 MD를 각각 대화에 제공한다. 요청받은 PDF도 같은 방식으로 제공한다. 출력 파일 인용이 지원되면 각 파일에 `:codex-file-citation{path="<최종 파일 절대경로>" purpose="output"}`를 쓴다. 전달 방식이 지원되지 않으면 첨부했다고 주장하지 않고 한계를 알린다.
- 각 최종 파일명과 대화에 표시되는 첨부파일 이름을 일치시킨다. 옵시디언용 MD에는 콜아웃·형광펜을, 메모용 MD에는 일반 인용문·굵은 글씨를 사용하며 두 파일의 내용은 동일하게 유지한다.
- 교정 전문은 명시적으로 요청받을 때만 전달한다. 원시 자막이나 전사본만 보내고 설교 정리를 완료했다고 보고하지 않는다.
